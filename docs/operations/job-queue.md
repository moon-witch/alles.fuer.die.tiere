# PostgreSQL job queue

Migration `0004` adds job status and per-attempt records. Apply it with `npm run db:migrate` from the private operations resource before deploying code that calls the queue. The migration does not alter public content.

`enqueueJob` accepts a stable dedupe key for one logical occurrence; an existing key returns the original job. `claimNextJob` leases one due job using `FOR UPDATE SKIP LOCKED`. A worker must finish within its lease, extend it before expiry, or let another worker reclaim it. A stale worker cannot mark a reclaimed job complete. Failures use exponential backoff with jitter; the last attempt becomes `failed`. `failExhaustedLeases` closes jobs whose final lease expired. Each attempt records its worker, times, outcome, and short error code.

The private worker image (`Dockerfile.worker`) processes `publication.verify` and `source.observe` jobs. `PUBLICATION_VERIFY_JOBS_ENABLED=true` on the web resource opts new publications into the queue after migration `0004` and worker deployment. The verification is read-only: it checks the immutable payload and, if the revision is still current, the public data reader. It does not issue an HTTP request or render HTML. A superseded revision is a successful check, not a new publication. Exhausted jobs create a steward attention item.

`SOURCE_OBSERVATION_JOBS_ENABLED=true` on the web resource moves new manual source captures to the worker. First give the worker the same internal `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET_RAW`, `S3_ACCESS_KEY` and `S3_SECRET_KEY` values as the web resource, and connect it to SeaweedFS's network. Redeploy the worker and confirm `worker.started` without repeated `worker.error`; then enable the web flag and redeploy it. The source form shows a queued status link, then a link to the private claim draft or the failure review queue. This job makes one attempt because the source operation itself records a failed fetch and a Needs Attention item; a new form submission with a fresh request key is the deliberate retry. With the flag absent or false, the form still captures synchronously. Keep worker concurrency at one on the launch server.

The worker can also schedule the first narrow official-source poll when `MA_FOREST_POLL_ENABLED=true` is set **on the worker**. It is disabled by default, writes only private observations, and is described in the [MA-Forest runbook](ma-forest-poll.md).

To check queue behavior against an isolated database, run `npm run test:jobs-db` after migrations. Do not run this integration script against production: it intentionally creates and changes test jobs.
